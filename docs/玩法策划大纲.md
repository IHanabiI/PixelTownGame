# PixelTownGame 玩法策划大纲

---

## 模块一：玩法大纲与背景设定

### 1. 项目一句话

`PixelTownGame` 是一款设定在日本温泉街的像素风轻经营叙事游戏。玩家从祖母留下的一家小拉面店起步，靠一碗碗热食重新点亮街上的灯火，逐步接手一间间老铺，最后把整条温泉街重新经营起来。

### 2. 核心创意

项目核心创意为：

`一碗灯火`

这不是单纯经营一家拉面店的游戏，而是从一间小店开始，逐步恢复整条温泉街生命力的经营故事。

### 3. 背景故事

主角从城市回到家乡温泉街。祖母病倒后，把一家只在傍晚到深夜营业的小拉面店交给了主角，也留下了一本旧账册。

这本账册里记着的不是金钱，而是街上的人情和规矩：

- 哪家旅馆会在晚饭后把客人送上街
- 哪间外汤散场后最容易带来客流
- 哪些老店还撑着暖帘，但已经后继无人

祖母生前常说：

`温泉街不是一排店，是一间没有屋顶的大旅馆。`

过去，这条街像一个整体运转。旅馆负责留客，浴场负责聚人，商店负责让客人停下来。现在，温泉还热，但街上的灯一盏盏灭了，很多店还在，生意却已经散了。

商店会给主角一个条件：

`如果你能在下一次大祭前，把这条街缺失的灯火一盏盏补回来，你就有资格优先接手那些即将关门的老铺。`

于是，玩家从祖母的拉面店开始，煮出回到这条街后的第一碗面。

### 4. 玩家为什么会在这条街上

玩家留在这条街上的理由分为三层：

- 替祖母把这家店守住
- 接下祖母留在街上的人情与约定
- 用经营成绩换取老铺暖帘的接手资格

玩家不是突然来创业，而是在“守住一家店”的过程中，慢慢变成“接下一条街的人”。

### 5. 玩家为什么要拓展业务到整条街

拓展整条街不是单纯为了赚更多钱，而是因为只守住拉面店，不足以让温泉街重新活起来。

温泉街的体验是连在一起的：

- 泡完汤的人需要牛乳和温泉蛋
- 夜里散步的人需要热食和停留点
- 白天游客需要土产和轻餐
- 旅馆送出来的客人，需要街上有东西可逛、可吃、可买

也就是说，玩家接手的不是更多店铺本身，而是温泉街缺失的一段段功能。

每接手一家店，都是在补全这条街的一部分：

- 接手 `牛乳摊`：补上泡汤后的第一口消费
- 接手 `温泉蛋摊`：补上边走边吃的温泉街感
- 接手 `土产小铺`：补上白天游客消费
- 接手 `小食堂 / 茶屋`：补上停留时间与休憩功能

最终目标不是商业帝国，而是把这条街重新经营成一个完整运转的整体。

### 6. 核心玩法机制

本作的核心机制分为六个层次：

#### 6.1 读街

玩家在开店前先观察街区状态，读取当前人流和时段特征。

需要判断的内容包括：

- 现在是白天、傍晚还是夜晚
- 现在是旅馆送客潮、外汤散场潮还是赶车潮
- 现在适合卖快餐、特色餐还是留客商品

#### 6.2 待客

顾客不是单纯点单，而是带着不同状态来到店里。

例如：

- 刚泡完汤
- 穿浴衣散步
- 赶末班车
- 下班后很累
- 带着孩子

玩家要根据顾客状态判断先服务谁、卖什么、要不要优先完成请求。

#### 6.3 点灯

玩家的经营结果会直接转化为街区变化。

不是只有金币增长，还包括：

- 街上的灯重新亮起
- 关着门的店铺重新开张
- 客人在街上停留更久
- 旅馆和商店会更愿意把人流引向这条街

#### 6.4 接店

玩家通过利润、口碑、关系和街区贡献度，逐步取得老店的经营权。

接店不是简单购买，而是带有日本温泉街式的“接暖帘”感觉：

- 接手
- 继承
- 代管
- 联营

#### 6.5 雇人

前期玩家自己做面、自己接客、自己看店。

随着生意做大，玩家可以开始雇佣帮工和店长：

- 后厨帮工
- 前台接待
- 送餐帮手
- 清洁收尾
- 店长 / 资深伙计

雇人会提高效率，但也会增加工资支出。

#### 6.6 治街

后期玩法不再只是管一家店，而是管理整条街的结构。

玩家要开始考虑：

- 哪些店先接
- 哪种店铺组合最能留客
- 白天和夜晚的重点是否不同
- 是否要办祭典活动
- 是否要和旅馆、浴场联动

### 7. 整体成长结构

游戏成长分为三个阶段：

#### 7.1 起步阶段

- 经营拉面店
- 认识街上的人
- 理解温泉街的客流节奏
- 先让祖母的店重新稳定下来

#### 7.2 扩张阶段

- 开始雇人
- 接手第二家、第三家店
- 形成基础多店经营
- 用不同店铺承接不同时间段的人流

#### 7.3 主导阶段

- 拿下关键店铺经营权
- 组织街区活动
- 与旅馆和浴场形成稳定联动
- 让整条街像“一间没有屋顶的大旅馆”那样运转

### 8. 当前版本定位

当前工程对应的是正式游戏中的第一阶段切片：

- 夜晚时段
- 单店经营
- 拉面店核心循环
- 少量街道观察
- 少量常客和特殊请求

也就是说，当前原型不是完整产品，而是正式产品中“第一盏灯亮起来”的那一段。

## 模块二：实现补充与细化构思

### 1. 当前原型对应内容

当前工程已经实现的内容：

- `Street -> RamenShop -> Summary` 闭环
- 夜晚街道移动
- 公告牌提示与 3 名 NPC 互动
- 顾客生成
- 三种拉面切换、制作、出餐
- 耐心系统
- 基础营收结算
- 三晚节奏配置

### 2. 当前原型数据

当前菜单：

- 酱油拉面 `shoyu`：12 金币，制作 1.6 秒
- 味噌拉面 `miso`：14 金币，制作 2.1 秒
- 温泉蛋拉面 `onsen`：18 金币，制作 3.0 秒

当前顾客：

- 旅人 `traveler`
- 常客 `regular`
- 上班族 `worker`

当前三晚配置：

- 第 1 晚：120 秒，10 秒刷一位顾客，目标 80 金币
- 第 2 晚：145 秒，8 秒刷一位顾客，目标 110 金币
- 第 3 晚：165 秒，6 秒刷一位顾客，目标 145 金币

### 3. 近期优先补充方向

建议优先补充以下内容：

1. 把固定请求改成请求池
2. 给顾客加入状态字段
3. 把顾客生成改成简单波次
4. 在结算中加入成本概念
5. 设计第一个可雇佣岗位
6. 设计第一家可接手的第二店

### 4. 可细化的系统模块

后续继续细化时，优先拆分以下模块：

- 顾客状态系统
- 请求池系统
- 雇佣与工资系统
- 第二店设定
- 街区热度与接店条件

### 5. 顾客状态草案

建议后续为顾客加入以下状态标签：

- 刚泡完汤
- 正在散步
- 赶时间
- 下班后疲惫
- 带着孩子
- 刚入住旅馆

这些状态将影响：

- 耐心
- 预算
- 商品偏好
- 请求触发概率

### 6. 雇佣系统草案

第一阶段建议只做最基础雇员：

- 后厨帮工：缩短制作时间
- 前台接待：延长顾客有效耐心

工资建议先做成固定扣除，后续再扩展为：

- 日薪
- 时薪
- 班次工资
- 熟练度工资差异

### 7. 第二店候选草案

第一家适合接手的第二店候选：

- 牛乳摊
- 温泉蛋摊
- 土产小铺

建议优先级：

1. 牛乳摊
2. 温泉蛋摊
3. 土产小铺

原因是牛乳摊最容易和泡汤后需求直接形成联动。

### 8. 后续文档细化规则

后续如果继续补充内容，建议保持以下规则：

- 模块一只改核心创意、背景故事、主玩法大纲
- 模块二只改系统实现、数据结构、玩法细化
- 新机制先写一句话作用，再写进入哪个阶段
- 避免在模块一写过多实现细节
- 避免在模块二重复背景故事
